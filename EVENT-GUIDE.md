# Agent Builders Club Build-a-thon

Welcome. This is a friendly, practical AI build sprint. You do not need a polished idea or a perfect codebase. A rough prototype, useful experiment, mockup, or well-documented failure is a valid result.

## Event details

- **Date:** Wednesday, August 19, 2026
- **Time:** 6:30–9:00 PM Central Time
- **Venue:** The Copper Wall, 1137 Burton Hill Rd, Fort Worth, TX 76114
- **RSVP:** [luma.com/o0jfobup](https://luma.com/o0jfobup)

## How it works

1. Join a team of 2–4 people.
2. Choose or draw a prompt.
3. Build with your team using whatever tools make sense.
4. Swap prompts once during the opening window.
5. Make something you can explain or demonstrate.
6. Give a short demo before the event ends.

Beginners are welcome. You can use code, no-code tools, AI agents, APIs, design tools, or a combination.

## Bring

- A laptop and charger
- Any accounts or tools you already use
- An idea of what you are curious about
- A willingness to work with people you may not know yet

## What counts as a good result

A good result is something your team can show clearly:

- A working prototype
- A useful workflow
- A compelling mockup
- A small tool or automation
- A surprising experiment
- A clear lesson from something that did not work

## Event-day repository workflow

The repository will become public on the morning of the event. Only submit work your whole team is comfortable sharing publicly.

1. Create a branch from `main`.
2. Create a folder under [`projects/`](projects/) using a short lowercase name with hyphens.
3. Copy the [`projects/_template`](projects/_template) README into your project folder.
4. Add your team, prompt, project summary, demo details, tools, status, and limitations.
5. Keep secrets, private data, and anything not cleared for public sharing out of the repository.
6. Commit your project to your branch.
7. Open a pull request against `main` with a title like `Add: Project Name`.
8. Ask an organizer to review and merge the pull request.
9. Make sure your pull request is open before demos begin, even if the project is still rough.

Organizers will merge project pull requests and update the project index after demos. If GitHub is unfamiliar, ask an organizer for help; someone can work with you at the event.

## Day-of timing

- **9:00 AM:** The repository is made public. Before then, the prompt bank is intentionally not published.
- **6:30 PM:** Arrive, meet people, and form teams.
- **Opening window:** Choose or draw a prompt. Teams may swap prompts once.
- **During the build:** Create a branch, document the project, and open a pull request when ready.
- **Before demos:** Make sure your pull request is open and your demo backup is ready.
- **Before the event ends:** Give your short demo and tell an organizer if your project needs an index update.

## Exact event timeline

The event is short, so we will use hard timeboxes. Organizers will give five-minute and one-minute warnings and move the group forward when time is up.

| Time | What happens |
|---|---|
| **6:30–6:40 PM** | Check in, grab a seat, and welcome. |
| **6:40–6:50 PM** | Form teams of 2–4. Organizers help match anyone arriving solo. |
| **6:50–7:00 PM** | Draw or choose a prompt. Each team may redraw once during this window. |
| **7:00–8:15 PM** | Build sprint. Organizers circulate and help teams reduce scope. |
| **8:15–8:25 PM** | Finish the project README, commit the work, open a PR, and prepare the demo backup. |
| **8:25–8:30 PM** | Stop building. Organizers reset the room and lock the demo order. |
| **8:30–8:57 PM** | Team demos and brief judge feedback. Each team gets a strict slot. |
| **8:57–9:00 PM** | Recognitions, final takeaway, and close. |

### Demo timebox

- **Up to 6 teams:** 3 minutes to demo + 1 minute for judge feedback.
- **7–9 teams:** 2 minutes to demo + 1 minute for judge feedback.
- The organizer will announce the final demo length after teams are counted.
- Teams should show one main path—not every feature. A screenshot or recording is acceptable if the live demo is fragile.
- A team that is not ready still gets its slot to explain the problem, what it tried, and what it learned.

## Ground rules

- Be kind and make room for beginners.
- Do not commit API keys, passwords, private data, or credentials.
- Do not use someone else's code, images, or data without permission.
- Be honest about what is real, mocked, unfinished, or broken.
- Only submit a team's project when everyone on the team is comfortable making it public.
